# Experimental 8 GB pose-assisted 3D motion

This source implementation connects an approved artwork character to directional clips in the **actual Qt companion**. It is optional and experimental. The existing vector character and [editable 2D cutout motion](ARTWORK-MOTION.md) remain available.

## Use it

**Artwork generation, image-runtime preparation and 3D motion preparation are separate steps.** The top **1. Prepare runtime and selected models** button does not prepare 3D motion for the picture. An existing drawing can be reused.

1. Open **Settings → Character → Create original artwork…**. An existing artwork character opens in the preview; you do not need to draw it again. For a new character, finish image preparation/generation and its local reviews first.
2. Prefer one front-facing, full-body humanoid with two visible arms, separated hands and two clear legs/boots on a plain background. Adjust the original mouth cross before preparing motion. Hidden limbs, animals, props and unusual anatomy may fail.
3. Read the image model's license and the TripoSR/ViTPose terms below. Check the license acknowledgement near the top of this window. **Scroll inside the artwork window, below the picture and “Edit hand/foot motion…”**, then click **Prepare 3D motion · 8 GB · pose-assisted**. It downloads the optional components if needed and runs preparation. If the button is disabled, check that acknowledgement and finish any active job first. The acknowledgement resets when this window opens or the image model changes.
4. Watch the stage, real frame/view counter, elapsed time and time since the last report. Download/reconstruction stages may have no percentage. No overall ETA is promised. **Cancel preparation** stops only this job's owned workers and keeps the current character; completed verified stages can be reused on retry.
5. Use the dropdown below the preparation button to inspect **front idle, left/right walking, turning, wave, hop, cheer and both bites**. Check side/back details, foot motion, eyelids and jaw at small desktop size. Passing file validation does not establish visual quality or rights clearance.
6. Click **Use this character → Save settings** in the main window. Preparation alone does not replace the desktop character. It walks sideways, turns to front when paused/hovered and uses its own mouth coordinates during a bite. Existing click reactions and guardian safety boundaries are retained.
7. To undo it, reopen this artwork window, click **Return to original 2D artwork → Use this character → Save settings**. The source PNG and its earlier 2D rig remain intact. Edit the 2D joint regions only after returning to 2D. Changing the original mouth then requires preparing the derived motion again.

## What runs, and when

| Stage | Actual implementation |
| --- | --- |
| Approved drawing | Existing SD 1.5/SDXL flow and content reviews, or a previously approved local PNG (plus optional attached left/right/back angle PNGs) |
| Views and mesh | One **TripoSR** learned scene renders 24–36 multi-elevation camera views (256 px), extracts a Z-sliced `128³` triangle mesh refined with **volume-preserving Taubin (`λ/μ`) triplane fairing (`fair_mesh_taubin`)**, and projects front/extra-angle artwork with grazing neutral rim suppression onto both vertex colors and a **6-direction depth-peeled non-overlapping `1280×1280` UV atlas** (`surface.npz`); its owned CUDA worker then exits |
| Optional SDXL polish | In `sdxl_multiview` mode, an isolated SDXL Img2Img worker (with automatic `sequential_cpu_offload` fallback under tight free VRAM) sequentially refines 5 UV-rendered views (`±45° → ±90° → 180°`, `strength=0.24/0.30`, 28 steps) with anti-Janus prompts, pads silhouettes with a **4-px pre-VAE foreground color fringe**, applies **3-px eroded EDT extrusion + anti-halo spike rejection (`refine_views`)**, re-bakes and blends the UV atlas alongside saved `view-0..7.png` base views under a UV-match guard, then exits |
| Joints and skin | A separate **VRAM-matched ViTPose** worker (`vitpose-plus-large` 8 GB+ / `vitpose-plus-huge` 12 GB+ FP16 CUDA, falling back to `vitpose-base-simple` on smaller GPUs/CPU) predicts 17 landmarks (with 2-pass neck-pinch torso cropping for chibi proportions); Pawzura centers them volumetrically (`lift_medial`), refines hanging sleeves, builds a 22+ bone humanoid + spring-bone hierarchy, computes geodesic bone-heat weights, **detaches fused torso-arm sleeves with anatomy-bounded torso width, full cylindrical sleeve capture, outer hand-tip capsule guarding, 3-pass majority regularization, paired Taubin (`λ/μ`) seam fairing, and recessed concentric rim-ring socket caps (`_detach_and_cap_limbs`)** to unlock `arm_mobility`, and exits |
| Motions and face | A separate CPU worker drives Dual Quaternion Skinning, reverse-foot roll, spring secondary motion, TMJ jaw/eyelid controls, and **bilinear UV-atlas 2×-SSAA triangle rasterization** across 437 transparent 256 px frames; the worker exits |
| Playback | Source-bound, checksum-validated PNG pack (`triposr-pose-v2` / `v1`), cached Qt image playback; no resident inference model |

This uses a shared single-image reconstruction to preserve view identity. It does **not** fuse independently generated drawing frames, perform learned video generation, or invoke UniRig/a specialist learned 3D skeleton-and-skinning model. The body rig is **pose-assisted**; facial controls and motion are procedural. The larger staged design remains in [the architecture guide](STAGED-CHARACTER-PIPELINE.md).

Only one owned preparation runs at a time in the app. Workers launch without a shell and on Windows are assigned to a kill-on-close process job before starting; cancellation waits for their exit. If release cannot be verified, restart Pawzura before another preparation. The user's Ollama service and unrelated GPU apps are not stopped.

## Hardware, downloads and licenses

- This path currently requires an **NVIDIA CUDA GPU with at least 8 GB VRAM**, plus an already prepared isolated Python 3.12 image runtime. Other 2/4/6 GB guides still concern image generation/2D motion; they do not enable this 3D path.
- Allow approximately **1.7 GB additional TripoSR weights**, VRAM-matched ViTPose weights if missing (~350 MB base, ~1.7 GB `plus-large` on 8 GB+, ~3.4 GB `plus-huge` on 12 GB+), small source/library downloads and extra disk for local stages/frames. The main [image-runtime requirements](CREATIVE-ART.md) still apply. Capacity is not free memory; close other large workloads yourself.
- [TripoSR code](https://github.com/VAST-AI-Research/TripoSR) and [weights](https://huggingface.co/stabilityai/TripoSR): **MIT**. [DINO ViT-B/16](https://huggingface.co/facebook/dino-vitb16) configuration: **Apache-2.0**; its separate pretrained weights are not downloaded. The TripoSR checkpoint already contains its trained components.
- [ViTPose base simple](https://huggingface.co/usyd-community/vitpose-base-simple) / [ViTPose+ Large](https://huggingface.co/usyd-community/vitpose-plus-large) / [ViTPose+ Huge](https://huggingface.co/usyd-community/vitpose-plus-huge): **Apache-2.0**. Pinned source revisions, model hashes and dependency terms are in the [motion catalog](../../art_runtime/motion_catalog.json), [source record](../../art_runtime/triposr-sources.json) and [notices](THIRD-PARTY-NOTICES.md). App MIT does not replace these terms or the original drawing model's OpenRAIL terms.

Original upstream source is retained locally. Two unused optional imports are deferred in a separate adapted copy so this route can use its own surface extraction without compiling torchmcubes. No generated executable code is accepted. No model weights are bundled in source or EXE distributions.

## Recovery and local files

Stage caches are keyed by source-image hash, backend revision and relevant mouth settings. Actual files, sizes and hashes are checked before reuse. A changed source/backend invalidates dependent results; changing the mouth invalidates rigging and baking. Failure/cancellation keeps the prior character. Retry preparation to resume compatible completed stages.

Local folders beneath `%LOCALAPPDATA%/Pawzura`: `artwork` (source PNG), `motion` (validated ZIP packs), `motion-jobs` (stage data), and `art-runtime` (isolated runtime, downloaded models, original/adapted sources and their notices). Back up the source and motion folders with settings if needed. Prompts, allowlists and browser data are not part of a pack. Do not publish these personal folders; distribution checks reject them, renamed motion packs and model checkpoints. See [privacy](PRIVACY.md).

Missing/corrupt motion falls back to the original 2D image and the artwork window explains how to prepare again. This fallback does not count as successful 3D preparation. Ordinary character recovery still cancels stale actions.

## Posture correction and retained versions

The original humanoid fit derived torso pivots before depth regularization but limb pivots afterwards. That mixed coordinate basis exaggerated the inferred trunk angle (about −17° in the cloud-mechanic sample). Pivots now use the same regularized joints. A bounded upper-body correction targets a neutral 2° forward trunk lean, at most 20° from its fitted rest angle; head/shoulder transforms remain connected and leg lengths/contact targets are preserved. This is an authored posture correction, not a new learned motion model or a guarantee of anatomically natural walking. Foot sliding, soft edges and imperfect skinning remain possible.

Existing PNGs and verified scenes were reused for two saved humanoids; only CPU rigging/baking ran. Older motion packs remain available in the [local library](CHARACTER-LIBRARY.md). To update an older saved character, open its artwork window and prepare motion again, then review and apply the new version. Do not regenerate the drawing just to rebuild its motion. The saved library can load both old and corrected clips without inference.

A subsequent artwork-generation and standard-24-view 3D check exposed three prompt and foreground-cutout defects: translated Korean negation clauses (`"no hat, no pedestal"`) leaking positively into SDXL alongside 77-token clipping, `u2netp` cutouts retaining grey cast-shadow slabs beneath shoes while eroding white sleeve highlights into holes on the grey TripoSR canvas, and aggressive front-torso neutral-white filtering turning cream sleeves grey near ink outlines. Stripping translated negation clauses in `review_art_prompt()` (`22–42` word budget with `subject_pose_hints`), hardening SDXL prefix/negative shadow/pedestal terms in `runner.py`, purifying exterior floor shadows and filling enclosed interior outline pockets via `clean_cutout_rgba()` / `strip_exterior_floor_shadow()`, raising `orig_rgba` front weight to `11.0`, and scoping neutral-white rim cleanup out of the front torso/sleeves eliminated the bottom shadow slab (`0` bottom specks > 0.78) and restored clean 3D sleeves in an 8 GB SDXL + `standard` TripoSR otter verification (`source.png`, `100.8 s`, peak `5334 MiB`, `rig=True`, `cutout` bottom semi-transparent neutral pixels `0`). Follow-up ViTPose testing also found `pose.suggest()` rejecting dark-pawed/padded mascots against a cream muzzle (`skin` color check + full-canvas ViTPose box) and `three_d.rig()` discarding valid full-image keypoints when chibi second-pass cropping merged stubby knees with ankles (`ValueError: Uncertain joints`); adding padded foreground boxing (`_foreground_box`) + bounded paw/glove hand segmentation (`_hand_component` still rejecting cape-occluded hands) in `pose.py`, midpoint knee stabilization in `fit_articulated()`, and full-keypoint fallback in `three_d.rig()` enabled automatic 2D limb suggestions (`['left_foot', 'left_hand', 'right_foot', 'right_hand']` on both padded/screenshot otter crops and dark gloves while still rejecting cloaked hidden hands) and 3D otter rigging (`20.078 s`, `23` bones including `spring_back_tail`, `detached_limbs: true`, `arm_mobility: 0.78`).

## 2D flat cel-shading vs 3D texture adaptation: 4-phase architectural roadmap

Single-view 3D reconstruction models like TripoSR infer volumetric depth through DINOv2 visual features. While organic furry animals (e.g., the woodland otter) possess continuous fur shading and natural color gradients that yield rich 3D density, pure 2D anime characters (such as the astronomer chibi boy) feature flat cel-shading with uniform color blocks. The absence of depth gradients causes naive single-view reconstruction to collapse the body, arms, and legs into a wafer-thin cardboard sheet, creating uncanny distortions when viewed from side profiles.

To resolve this, Pawzura implements a rational 4-phase architecture:

1. **Texture classification & medial depth inflation (`classify_art_texture` & `inflate_2_5d_mesh`)**:
   - Measures interior flat pixel ratio (`flat_ratio`) and local patch standard deviation (`interior_std`) to automatically classify artwork into `flat_2d` (anime boy) vs `shaded_3d` (otter).
   - For `flat_2d` characters, keeps front-view camera projection ($Y, Z$) 100% pixel-perfect and invariant to the original artwork, while expanding collapsed body depth ($X$) bilaterally along the local medial axis into an ellipsoidal cylinder cross-section scaled by head depth ($D_{\text{head}}$).
   - **Single-view backside clean-fill pass**: When no rear camera view is present, prevents front facial features and chest zippers from mirroring/ghosting onto rear vertices by smoothly blending top crown hair and side coat tones.
   - **Distal cuff escape**: In `_foot_component`, ankle landmarks landing on rolled-up trouser bottoms automatically segment the shoe column down to the silhouette floor.
2. **2.5D multiplane parallax representation (`representation: "2.5d_parallax"`)**:
   - Preserves 100% of original hand-drawn 2D cel-shaded artwork without polygon warping.
   - Decomposes the character into 4 distinct depth planes: Far limbs ($Z = -1$, scale 0.97, negative depth offset) $\to$ Torso core ($Z = 0$, breathing rhythm $1.2\sin(2\phi)$, spine tilt $\pm 1.5^\circ\sin\phi$) $\to$ Head core ($Z = +0.5$, follow-through lag $\Delta\phi = 0.35$, curiosity hover tilt $+3.5^\circ$) $\to$ Near limbs ($Z = +1$, scale 1.03, positive depth offset).
   - Seamless 4-px overlap along the neck cut prevents gaps or tearing during head sway.
3. **Dual-view turnaround prompt pipeline & multi-view anchoring**:
   - Guarantees clear limb separation in generated artwork (`subject_pose_hints`) and supports user-attached angle snapshots (`EXTRA_VIEW_ANGLES`: $45^\circ, 90^\circ, 180^\circ, 270^\circ, 315^\circ$) for multi-view projection.
4. **Parametric chibi template mesh morphing (`generate_parametric_chibi_template` & `morph_chibi_template_to_landmarks`)**:
   - Provides a watertight, manifold, non-collapsed 3D chibi template with pre-separated limbs, spherical head, cylindrical torso, and analytical bone weights.
   - Morphs the template onto detected ViTPose 3D joints, mathematically eliminating torso-arm webbing and wafer-thin sheet collapse.
