# 캐릭터를 로컬에 저장하고 재사용하기

캐릭터 생성에는 몇 분이 걸릴 수 있습니다. 승인한 그림과 준비한 애니메이션을 보관해 저장한 캐릭터를 쓸 때 Ollama·그림 생성·3D 복원·리깅을 다시 실행하지 않도록 합니다.

## 저장과 불러오기

- **자동:** 생성에 성공한 그림과 준비에 성공한 3D 모션을 각각 별도 로컬 버전으로 저장합니다. 바탕화면에 적용하기 전에도 보관하며 완료 메시지에서 확인할 수 있습니다. 실패·거절된 생성은 추가하지 않습니다. 자동 저장 실패 시 현재 캐릭터와 생성 파일은 유지하므로 저장 공간 문제를 해결한 뒤 수동 저장으로 재시도하세요.
- **이름 붙이기:** **설정 → 캐릭터 → 캐릭터 저장…**에서 1–64자 이름을 입력합니다. 그림 창의 같은 버튼은 승인한 미리보기를 저장합니다. 같은 설정을 자동 저장해도 이름을 유지하며 동일한 버전에 직접 이름을 붙이면 복제 대신 표시 이름을 갱신합니다.
- **복원:** **저장한 캐릭터…**에서 버전을 선택해 미리 보고 **이 캐릭터 사용 → 설정 저장**으로 적용합니다. 미리보기만 하거나 보관함을 닫으면 바탕화면은 바꾸지 않습니다. 그림 창의 보관함에는 그림 버전만 표시하고 메인 캐릭터 탭에서는 도형 디자인도 지원합니다.
- 그림·입 위치·2D 손발 리깅·동작 묶음이 바뀌면 별도 버전이 됩니다. 이전 승인 버전과 픽셀·클립은 유지합니다. 현재 캐릭터와 최근 20개 외형 이력은 보관함과 별개입니다.

선택기는 적용 직전 원본·모션을 다시 검증합니다. 자산이 없거나 손상되면 현재 캐릭터를 유지하므로 무조건 재생성하기보다 백업을 복원하세요. 준비한 3D 결과가 마음에 들지 않으면 원본 2D 버전도 사용할 수 있습니다.

## 보관하는 내용

일반 실행에서는 `%LOCALAPPDATA%/Pawzura` 아래에 저장합니다.

| 폴더 | 내용 |
| --- | --- |
| `character-library` | 이름 있는 `.pawzura-character.json`: 검증한 외형·원본/애니메이션 해시·입/2D 관절 설정 |
| `artwork` | 승인한 원본 PNG 픽셀 |
| `motion` | 프레임별 입 좌표가 있는 검증한 투명 방향별 클립 |
| `motion-jobs` | 검증한 중간 시점·표면 메쉬·관절/가중치·단계 기록 |
| `art-runtime` | 별도 선택 실행환경·모델 다운로드·소스·원본 고지 |

재생 복원과 중간 작업 재사용을 모두 원하면 **설정과 `character-library`·`artwork`·`motion`·`motion-jobs`를 함께 백업**하세요. 보관함 JSON은 자산을 참조하며 픽셀을 담지는 않습니다. 실행환경·모델 캐시는 크고 복사는 선택 사항입니다. 재배포한다면 구성요소 조건을 유지하세요. 개인 폴더를 공개 앱 배포에 넣지 마세요. 별도 설정 경로를 쓰는 개발 확인용 앱은 그 임시 설정 옆에 보관함을 둘 수 있습니다.

보관함은 최대 500버전을 지원합니다. 캐릭터를 바꿔도 이전 저장본을 자동 삭제하지 않습니다. 아래 삭제 기능으로 저장 공간을 관리하세요.

## 필요 없는 버전 삭제

1. **설정 → 캐릭터 → 저장한 캐릭터…**에서 버전을 선택합니다.
2. **삭제…**를 누릅니다. **다시 쓰지 않는 파일도 함께 삭제**는 기본으로 켜져 있습니다. 체크를 끄면 보관함 항목만 지우고 그림·모션·캐시 파일은 모두 남깁니다.
3. 예상 정리 용량과 파일 수를 확인한 뒤 **삭제…**로 승인합니다. 기본 선택은 **취소**입니다. 휴지통을 쓰지 않는 영구 삭제이므로 필요한 결과는 먼저 백업하세요.

현재 적용 중이거나 적용 대기 중인 버전은 삭제할 수 없습니다. 다른 캐릭터를 선택해 **설정 저장**한 뒤 삭제하세요. 다른 저장본·현재/적용 대기 캐릭터·최근 20개 외형 이력이 공유하는 파일은 보호합니다. 따라서 보관함 항목을 지워도 외형 이력에 남은 그림 때문에 확보 용량이 작을 수 있습니다. 더 이상 쓰지 않는 원본 PNG·모션 ZIP·확인된 완료 단계 캐시는 정리할 수 있으며 모델 다운로드와 실행환경은 유지합니다. 선택한 버전의 파일 정리 기능이며 모든 오래된 고아 파일을 검색하는 기능은 아닙니다.

승인 후에도 참조와 파일 상태를 다시 확인합니다. 그 사이 바뀌었다면 다시 확인·승인하세요. 진행 중이거나 인식/검증하지 못한 캐시·파일은 유지합니다. 파일이 잠겨 있거나 일부 정리만 성공하면 삭제한 용량을 안내하고 가능하면 항목을 남겨 재시도할 수 있게 합니다. 관련 준비 작업을 마친 뒤 재시도하고 공유 폴더를 직접 지우지 마세요. 원본이 없어 **이 캐릭터 사용**이 비활성화되어도 보관함 항목은 삭제할 수 있습니다.

## 중간 결과 재사용

재준비 전에 단계 입력·원본 해시·파일 크기/해시·백엔드 지문을 검증합니다. 복원·리깅·프레임 저장의 지문을 분리해 동작 계산만 바뀌면 그림·장면·호환 리깅을 재사용하고, 리깅 수정 시에는 장면을 재사용해 관절/가중치·클립만 다시 만듭니다. 원본·모델·복원 입력이 바뀌면 후속 결과는 무효화합니다. 이전 캐시는 고정한 해당 알고리즘과 실제 출력 해시가 맞는 경우에만 가져오며 모르는/호환되지 않는 캐시는 다시 계산합니다. 캐시는 중복 작업을 줄이지만 큰 모델의 개별 메모리 요구량을 없애지는 않습니다.

첫 자세 수정은 승인한 그림과 검증한 TripoSR 장면을 재사용했습니다. 캐릭터를 다시 그리거나 GPU 복원을 다시 실행하지 않았습니다. 리깅 수정 때문에 CPU 포즈 추정과 프레임 저장은 다시 했으며, 동작만 바꾸는 회귀 검사에서는 프레임 저장만 실행함을 확인합니다. 두 번째 저장된 사람형 캐릭터의 검사도 이 모의 검사와 구분합니다.

## 로컬 개인정보와 권리

프롬프트·브라우저 목록·연결 코드·자격 정보·컴퓨터 경로는 보관함 정보에 넣지 않습니다. 생성물·직접 지은 이름은 개인 로컬 데이터로 취급하세요. 기본 위치는 저장소 밖이며 `.gitignore`가 보관함·모션/단계/소스 폴더·항목 확장자·모델 체크포인트를 제외합니다. 배포 검사도 해당 폴더와 식별 가능한 이름 바꾼 보관함 JSON을 거절합니다. 개인 데이터를 강제로 Git에 추가하지 마세요. ignore 규칙은 접근 통제 기능이 아닙니다.

저장했다고 생성물의 권리가 확보되지는 않으며 원래 그림·모델·구성요소 조건은 유지됩니다. [고지](THIRD-PARTY-NOTICES.md)와 [3D 한계](3D-MOTION.md)를 참고하세요. 이 기능으로 모델 가중치나 생성 캐릭터 데이터를 Git에 추가하지 않습니다.
