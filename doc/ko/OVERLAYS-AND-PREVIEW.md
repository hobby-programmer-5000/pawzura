# 오버레이 공격·미리보기 반복·걷는 높이

## 0.1.6에서 바뀐 내용

이전 창 검사는 화면에 표시되고 소유자가 없으며 제목이 있는 창이면, 화면 전체의 투명 오버레이 호스트나 내장 자식 화면도 후보로 받아들였습니다. 일반 닫기 버튼이 없는 그래픽 오버레이에도 오른쪽 위의 추정 좌표를 깨무는 표시가 나올 수 있었습니다. 오버레이 내용만 숨겨도 호스트 창 자체는 창 목록에 남을 수 있습니다.

이제 자식·도구·비활성·클릭 통과 창을 제외하며 시스템 메뉴가 있는 창만 대상으로 삼습니다. 알려진 그래픽·오버레이·세션 보조 프로세스와 WebView2 렌더러는 편집 가능한 허용 목록과 별개로 보호하고, 실제 닫기 직전에도 차단합니다. 예전 프로그램 목록을 쓰더라도 보조 화면을 보호합니다. 시스템 메뉴가 없는 일부 사용자 정의·테두리 없는 앱은 의도적으로 건드리지 않으므로 모든 앱을 강제 제어하는 도구는 아닙니다.

프로그램 미리보기는 계속 열린 동일 대상에 대해 재사용 대기 시간마다 반복하지 않고 한 번만 표시합니다. 새 창·제목 또는 설정 적용 후 다시 시연할 수 있습니다. 미리보기에서 만든 콜백은 실행 전에 미리보기를 꺼도 실제 닫기 요청으로 바뀌지 않습니다.

균열·탭 표식 창은 캐릭터가 소유하고 재사용합니다. 활성화되지 않는 도구 창이며 작업표시줄 버튼을 요청하지 않습니다. 효과 중 창 생성·제거를 줄이지만 모든 그래픽 합성·GPU 깜빡임이 없어진다고 검증한 것은 아닙니다.

점프가 끝나면 예전 출발 높이를 그대로 복원하지 않고 현재 모니터의 바닥 높이로 돌아옵니다. 깨무는 순간 취소돼 복구된 좌표를 이전 점프가 다시 덮어쓰지도 않습니다. 걷는 기준은 모니터 작업 영역이며 화면 구성·자동 숨김은 실기기별 확인이 필요합니다.

## 반복해서 깨물거나 깜빡일 때

1. 먼저 트레이의 **집중 지킴이 끄기**를 사용하세요. **캐릭터 숨기기**는 표시를 숨기고 **종료**는 앱을 멈춥니다. 설정 창만 닫으면 트레이에 남습니다.
2. 이전 앱을 종료하고 0.1.6 이상의 ZIP 전체를 사용하세요. 진단을 위해 그래픽 드라이버나 탐색기 프로세스를 강제 종료하지 마세요.
3. 위치가 잘못되면 **캐릭터 화면 복구**를 누르세요. 실제 닫기를 다시 켜기 전 미리보기로 확인하세요.
4. 문제가 남으면 앱 버전·미리보기 여부·대상 프로세스의 **파일명**과 Pawzura를 완전히 종료해도 계속되는지 기록하세요. 개인 사이트 목록이나 문서 제목이 있는 화면은 첨부하지 않는 편이 좋습니다.

작업표시줄 깜빡임, 오버레이 창 숨김·재생성과 프로세스 재시작은 서로 다른 현상입니다. PID·시작 시각, 창 수명과 충돌 기록을 따로 확인해야 합니다. 짧은 관찰 구간이 안정적이었다고 과거 상황까지 확정할 수 없으며, 구석의 애니메이션만으로 프로세스 종료를 단정할 수도 없습니다. [실제 검증 범위](VALIDATION.md)를 참고하세요.

진단은 읽기 전용 창·프로세스 정보와 테스트가 만든 안전한 창만 사용합니다. 사용자 창 제목·사이트 목록·개인 경로·원시 프로세스 목록을 배포물이나 이 안내에 넣지 않습니다.
