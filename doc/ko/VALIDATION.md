## 0.1.9 테마와 고급 모델 기준

**로컬 Python 99개·확장 19개 검사가 통과했습니다.** 테마 미리보기와 저장·재실행, 이전/잘못된 설정 이관, VRAM 기준 명시 선택, 모델 선택 저장과 기준 축소 시 목록 제거, 허용 목록 프로필 분리, 정확한 모델 식별자·JSON 형식·비사고·사용 후 해제 요청, 백엔드 내용을 노출하지 않는 오류 코드를 검사합니다. 처음 제한 환경에서는 임시 디렉터리 ACL과 Node 하위 프로세스 EPERM 오류가 났고 일반 권한의 합성 검사에서 통과했습니다. 테마 검사 하나는 동등한 기본 목록의 정렬 차이를 비교했으며, 기존 저장 정규화를 거친 기준으로 수정했습니다.

임시 예시 설정으로 한영 라이트·다크 화면을 820×640·920×720에서 렌더링합니다. 첫 offscreen 캡처는 Windows 폰트가 없어 검증에 쓸 수 없었고, 폰트를 등록한 캡처로 교체했습니다. 공식 모델 카드·라이선스·파일 메타데이터를 확인하고 원문과 공개 모델 목록을 포함합니다. 신규 Qwen3 가중치를 받아 기기 추론 검사를 하지는 않았습니다. 2·4·6·8GB는 실측 메모리·속도·품질 보장이 아닙니다. 기존 0.5B/1.5B 추론 증거와 기기·브라우저 검증 한계는 유지합니다.

0.1.9 EXE의 스모크 렌더링·정상 종료를 확인했고 내장 버전·앱 모듈 10개가 컴파일한 최종 소스와 일치했습니다. 처음 marshal 바이트 비교는 참조·문자열 내부 공유 배치도 비교했으며, 코드 객체 비교로 수정하지 않은 브리지의 일치를 확인한 뒤 10개 모두를 검사했습니다. 실제 사용자 감시·탭·설정은 사용하지 않았습니다.

## Windows 11 제작자 수동 확인 보고

0.1.7 관련 대화에서 제작자가 Windows 11에서 앱을 대략 확인했다고 보고했고 추가 문제는 보고하지 않았습니다. 직접 사용한 수동 확인 결과로 기록합니다. 정확한 앱·Windows 빌드, 하드웨어, 브라우저 버전과 항목별 체크리스트는 제공되지 않았으므로 이 보고만으로 특정 기능이나 브라우저 흐름 각각을 통과 처리하지 않습니다. 기기 식별 정보나 개인 설정은 포함하지 않습니다.

이에 따라 Windows 11을 첫 사용자 확인도 하지 않은 환경으로 표시하던 문구를 갱신했습니다. Windows 11의 여러 구성에서 반복 가능한 검사와 사용자 브라우저 프로필의 상세 E2E 항목별 기록은 남아 있습니다. 아래 자동 검사·격리 브라우저 결과는 각각 명시한 범위를 따릅니다.

## 0.1.6 오버레이 필터와 미리보기 수명

로컬에서 **Python 77개·확장 19개** 검사가 통과했습니다. 시스템 메뉴가 있는 일반 창과 오버레이·도구·비활성·클릭 통과·자식 창의 구분, 대상 선정·닫기 경계의 그래픽/렌더러 보호, 프로그램 미리보기 1회, 모드 변경 뒤 미리보기 콜백, 효과 창 재사용, 잘못된 복귀 높이와 깨무는 중 취소를 검사했습니다.

읽기 전용 실제 창 검사에서 예전 기준이 그래픽 오버레이·내장 렌더러 화면을 대상으로 받는 것을 확인했습니다. 예전 판단 코드에 현재 메타데이터를 주고 표시·닫기를 시험 함수로 대체하자 우측 상단의 해당 대상들을 선택했고, 미리보기 닫기 호출은 0회였습니다. 새 실제 창 판별에서는 두 화면 모두 제외됐습니다. 정상 테스트 창의 일반 닫기는 유지되며, 안전한 미리보기 두 번에서 효과 HWND 재사용·TOOLWINDOW/NOACTIVATE·APPWINDOW 미지정을 확인했습니다. 이 제한된 시험 동안 그래픽·탐색기 프로세스 집합은 그대로였고 확인 당시 모니터 작업 영역과 실제 셸 작업표시줄 좌표도 일치했습니다.

조사 시점에 실행 중인 Pawzura가 없어 예전 감시 앱을 가동한 상태의 깜빡임·재시작 전체를 **재현한 것은 아닙니다.** 프로세스와 최근 충돌 기록이 안정적이었다고 과거 상황 전체를 확정할 수 없습니다. 진단을 위해 드라이버·탐색기를 종료·재시작하지 않았으며 원시 식별 정보·제목·개인 경로·프로세스 목록을 동봉하지 않습니다. [오버레이 문제 해결](OVERLAYS-AND-PREVIEW.md)을 참고하세요.

0.1.6 Windows EXE의 오프스크린 렌더링·정상 종료와 내장 앱 모듈 10개의 최종 소스 일치가 통과했습니다.

실제 격리 Chromium에서 설치된 ID와 공개 manifest key가 일치하고, 도우미의 옵션 바로가기가 브라우저·포트를 입력해 테스트가 승인한 뒤 연결됨을 확인했습니다. 허용·옵션 탭과 마지막 탭 뒤 창 유지도 통과했습니다. 영문·한글 도우미와 설정 화면은 임시 기본값·일반 경로로 렌더링해 검토했습니다.

최종 0.1.5 Windows EXE의 오프스크린 렌더링·정상 종료가 통과했습니다. 내장 앱 모듈 10개가 최종 소스와 일치했고 이전 0.1.3·0.1.4 릴리스 ZIP 체크섬도 그대로였습니다. 완료 표시는 예전 확장의 주소 검사 통신이 아니라 새 인증 상태 확인이 있어야 표시합니다.

사용자 Chrome의 개발자 모드·폴더 선택창 클릭 전체를 **자동 검증한 것은 아닙니다.** 앞선 데스크톱 제어 도구는 현재 주소를 확실히 파악하지 못해 중단됐습니다. 도우미의 브라우저 실행 호출은 단위 검사하고, 확장을 불러온 뒤의 연결 링크는 격리 Chromium에서 확인했습니다. Firefox·Zen과 다른 브라우저 UI는 별도 실기기 검증이 필요합니다. 이 검사에는 사용자 브라우저 프로필·목록을 쓰지 않았습니다.

## 0.1.4 브라우저 탭 표시

로컬에서 **Python 61개·확장 18개** 검사가 통과했습니다. 미리보기·실제 동작의 활성·백그라운드 탭 이벤트는 작업표시줄 근처의 별도 표식만 사용하며 현재 창 조회·일반 창 닫기 좌표·일반 창 닫기 함수가 호출되지 않음을 검사합니다. 티켓 만료 이후로 시간을 이동해 미리보기 반복·닫기가 없고, 허용 주소 이동·설정 적용 후 다시 시연됨을 확인합니다. 표식의 화면 내부 위치와 취소 시 제거, 기존 허용 탭·이동 후 닫기 취소·미리보기·마지막 탭 뒤 창 유지 검사도 통과했습니다.

영문·한글 표식 렌더링을 검토했습니다. 실제 Windows 검사에서는 하단 표식에서 미리보기 한 번을 완료하고 현재 창 조회·일반 창 닫기를 호출하지 않았습니다. 격리된 실제 Chromium에서도 차단 탭만 제거, 허용·옵션 탭 보호와 마지막 탭 뒤 창 유지가 통과했습니다. 0.1.4 EXE 실행 검사와 내장 앱 모듈 9개의 최종 소스 일치를 확인했고, 기존 0.1.3 출력 파일 419개가 체크섬상 그대로임을 확인했습니다. 별도 `dist/0.1.4` 출력 폴더와 임시 설정을 사용했습니다.

## 발견하여 보정한 환경 문제

- Conda의 Python/Qt DLL 조합에서 QtCore import가 실패했습니다. 소스 실행 안내는 일반 CPython 전용 가상환경을 기본으로 합니다.
- PyInstaller가 서로 다른 Python/Qt/Shiboken 휠의 MSVC DLL을 포함하면, Windows가 먼저 로드한 구버전 런타임 때문에 QtCore import가 실패할 수 있습니다. 빌드 스크립트는 포함된 원본 Microsoft DLL 중 파일 버전이 가장 최신인 것을 동일 이름의 모든 배포 위치에 일관되게 복사합니다. Microsoft DLL 자체를 패치하지 않습니다.
- Qt offscreen 플러그인은 Windows 시스템 글꼴을 자동으로 찾지 못해 검사 전용 경로에서 시스템 Segoe UI와 맑은 고딕을 명시적으로 불러옵니다. 글꼴 파일은 재배포하지 않습니다.
- frozen EXE의 검사 종료 시 Qt 객체 정리 순서 문제를 발견하여, 검사 창과 타이머를 명시적으로 정리한 뒤 종료하도록 수정하고 정상 종료를 확인했습니다.
- Windows의 venv 실행기 PID와 실제 GUI Python PID가 달라질 수 있어 native probe는 자식 프로세스가 보고한 실제 PID로 대상을 검증합니다.
- 자동화 도구의 실제 창 스크린샷 캡처가 타임아웃되어, 시각 검토는 앱 자체 Qt 렌더링 캡처를 사용했습니다. 사용자 트레이 클릭부터 종료까지 전체 UI 조작을 자동 검증했다고 주장하지 않습니다.

## 별도 검증이 필요한 범위

- 위 Windows 11 수동 보고 외에 여러 Windows 11 구성의 반복 검사, Windows 10 1809 최소 버전, ARM64, 원격 데스크톱 세션.
- 로컬에서는 Python 3.14.7, GitHub의 Windows runner에서는 Python 3.12/3.14/3.15를 검사했습니다. 이는 모든 Windows 구성·CPython 패치 버전의 확인을 대신하지 않습니다.
- 실제 사용자 프로필에서 Chrome/Edge/Firefox 버전별 설치·연결·탐색·탭 닫기 E2E의 항목별 기록. 위 격리 Chromium 검사와 제작자의 일반 사용 확인은 각각 별도의 범위입니다.
- Firefox 영구 설치를 위한 Mozilla 서명과 각 스토어 배포.
- 커스텀 창 프레임의 정확한 X 위치, 브라우저 실제 탭 X 위치, 관리자 권한 창의 닫기 거절, 전체 화면 앱과 가상 데스크톱.
