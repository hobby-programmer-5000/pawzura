# 증거·재시도·복구 절차

큰 변경이나 여러 세션에 걸친 작업에 사용합니다. 간단한 문구 수정은 관련 검사와 결과 보고로 충분하며 감사 서비스나 JSON을 강제하지 않습니다. 다음은 작업 규칙이며 새 실행기·CI 차단·권한 제어를 설치하는 작업이 아닙니다.

## 시험한 스냅샷 확인

수정 전 시작 커밋·기존 미커밋 경로를 기록합니다. 작업 정의에서 예상 수정 경로·보존할 동작을 합격 조건별 검사에 연결하고 연관 파일이 늘면 확장 이유를 남깁니다. 동시 작업·충돌·실험 때문에 필요하면 별도 worktree를 쓰되 기존 미커밋 작업은 별도로 보존합니다. worktree는 호스트 인증 정보·네트워크를 격리하지 않습니다. [Git 공식 설명](https://git-scm.com/docs/git-worktree)을 참고하세요.

의미 있는 검증마다 시험한 커밋 또는 작업 중 diff/파일 해시를 식별합니다. 시작 커밋만으로는 미커밋 수정을 식별할 수 없습니다. 이전 검사를 무효화하는 환경·입력·생성물 변경도 적습니다. 새 결과는 해당 스냅샷과 검사 범위에만 적용합니다.

## 합격을 뒷받침하는 증거

- 실제 명령 종료 상태와 공유 가능한 출력 위치를 기록합니다. 여러 명령은 관련 종료 상태를 각각 확인하고 마지막 명령 성공이 앞선 실패를 가리지 않게 합니다.
- 의도한 대상에서 필요한 검사가 실행됐는지 확인합니다. 수집된 테스트 없음·관련 테스트 전부 건너뜀·과거 로그·다른 EXE 버전은 합격 증거가 아닙니다. 문법·린트·타입 검사만으로 실행 동작까지 검증하지 않습니다.
- 회귀 검사는 신고된 실패를 다루고 수정 뒤 통과하는지 봅니다. 안전하게 재현 가능하면 수정 전 실패도 확인하며 불가능하면 그 한계를 명시합니다.
- 환경·간헐 오류로 의심되면 실패 특징과 재시도 이유를 보존합니다. 처음 실패와 이후 결과를 구분하고 원인 불명 간헐 실패는 열린 문제로 남깁니다.
- PASS·FAIL·NOT RUN·USER REPORTED와 절차·환경·남은 빈틈을 함께 씁니다. UI·수동 확인도 관련 자동 검사뿐 아니라 관찰 가능한 단계·결과가 있어야 합니다.

## 재시도와 실패 유형 개선

새 증거 없이 같은 원인의 실패가 두 번 반복되면 해당 동작을 되풀이하지 않습니다. 구현·문맥 부족·잘못된 대상/버전·의존성/환경·권한 거절·외부 서비스 원인을 구분합니다. 허가된 다른 가설로 전환하거나 정확히 빠진 입력을 기록하고 독립적으로 가능한 일을 계속합니다. 명시적 도구 중단은 우회하지 않습니다. 엄격한 시간·예산·반복 횟수 제한은 실제 실행기 지원이 있어야 합니다.

diff와 증거를 보존하고 전체 작업 공간을 자동 restore/reset/clean하지 않습니다. 되돌릴 필요가 있으면 안전하게 분리되는 에이전트 변경과 사용자 허가부터 확인합니다. 검사 통과를 위해 사용자 작업을 지우지 않습니다. 실제 작업 상태에 따라 패치 보존·범위를 좁힌 취소·분리된 실험을 선택할 수 있습니다.

확인된 반복 실패는 가장 작은 절차 개선을 고릅니다. 동작 문제는 회귀 검사, 도메인 사실 부족은 범위별 안내, 취약한 반복 작업은 전용 도구로 보완합니다. 해당 실패를 다루는지 확인한 뒤 상시 규칙으로 올리며 미확정 진단 하나를 일반화하지 않습니다.

## 선택적 기계 판독 실행 기록

확인한 스냅샷마다 Git에서 제외된 `.cache/agent-work/runs/<run-id>/receipt.json`을 새로 만들고 공개해도 되는 증거를 옆에 둡니다. 이전 기록을 보존하고 받아들인 결과를 조용히 덮어쓰기보다 정정/대체 기록을 새로 남깁니다. STATE.md는 현재 유효한 기록을 가리킵니다. 이는 보존 관례이며 암호학적 불변성·충돌 뒤 복구 보장은 아닙니다.

아래는 실행하지 않은 예시입니다. `null`은 측정/확인 불가이며 0이 아닙니다. 리비전·해시·명령은 실제 결과로 채우고 무관한 필드는 생략하세요. 사용량·검토자·성공한 테스트 개수를 지어내지 않습니다.

```json
{
  "schema_version": 1,
  "run_id": "EXAMPLE_ONLY",
  "base_commit": null,
  "tested_snapshot": {"kind": "working-tree-diff", "sha256": null},
  "changed_paths": ["path/to/file"],
  "checks": [
    {
      "criterion": "예시 합격 조건",
      "command": null,
      "exit_code": null,
      "result": "NOT RUN",
      "tests_collected": null,
      "tests_skipped": null,
      "duration_seconds": null,
      "evidence": null
    }
  ],
  "review": {"kind": "self", "findings": []},
  "outcome": "NOT RUN",
  "unresolved": ["설명용 예시이며 실제 검사를 실행하지 않음"],
  "final_commit": null,
  "artifact_sha256": null,
  "usage": {"model": null, "tokens": null, "cost_usd": null}
}
```

실행 기록·증거에 개인정보·비밀·개인 diff 원문·기기 경로·공유할 수 없는 stdout을 넣지 않습니다. 검토된 비민감 입력/파일의 해시만 기록합니다. 내용을 생략해 검증 범위가 줄었다면 그 사실을 표시합니다. 최종 커밋은 생성된 뒤 기록하며 같은 커밋 안의 기록이 자신의 최종 커밋 해시를 담을 수 있다고 주장하지 않습니다.

독립 검토가 요청됐고 가능하면 원래 합격 조건·코드 diff 원문·공유 가능한 실행 기록을 제공합니다. 특정 코드/증거·영향·수정 방법을 연결한 지적을 받고 수정된 스냅샷을 재검사합니다. 별도 검토자가 없으면 자기 검토로 기록합니다. 참고 글의 사례만을 이유로 다른 모델·추론 수준이나 자동 위임을 지정하지 않습니다.
