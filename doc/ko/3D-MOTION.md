# 실험용 8GB 포즈 추정 보조 3D 움직임

승인한 창작 그림을 **실제 Qt 바탕화면 캐릭터**의 방향별 클립에 연결하는 소스 구현입니다. 선택형 실험 기능이며 기본 도형 캐릭터와 [2D 손발 조각 편집](ARTWORK-MOTION.md)도 계속 사용할 수 있습니다.

## 사용 순서

1. **설정 → 캐릭터 → 창작 그림 만들기…**를 엽니다. 기존 그림 캐릭터라면 미리보기에 그대로 불러오므로 다시 그릴 필요가 없습니다. 새 캐릭터는 먼저 그림 준비·생성과 로컬 검사를 끝내세요.
2. 단순한 배경에 정면 전신, 두 팔·손이 몸통과 떨어져 있고 두 다리·부츠가 명확한 사람형이 유리합니다. 동작 준비 전에 원본 입의 십자 위치를 맞추세요. 숨겨진 팔다리·동물·소품·특이한 신체는 실패할 수 있습니다.
3. 그림 모델 라이선스와 아래 TripoSR·ViTPose 조건을 읽고 창 상단의 라이선스 확인란을 선택합니다. **3D 움직임 준비 · 8GB · 포즈 추정 보조**를 누르면 필요한 선택 구성요소를 받고 준비합니다. 버튼이 비활성화라면 확인란과 진행 중인 작업을 먼저 확인하세요.
4. 현재 단계·실제 시점/프레임 수·경과 시간·마지막 보고 후 시간을 확인하세요. 다운로드·복원에는 백분율이 없을 수 있으며 전체 완료 예상 시간은 약속하지 않습니다. **준비 취소**는 이 작업이 만든 프로세스만 종료하고 현재 캐릭터를 유지합니다. 재시도 시 검증한 완료 단계를 재사용합니다.
5. 준비 버튼 아래 목록에서 **정면 대기, 좌우 걷기, 돌기, 손 흔들기, 뛰기, 응원, 양쪽 깨물기**를 살펴보세요. 작은 바탕화면 크기에서 측·후면, 발 움직임, 눈꺼풀·턱을 확인합니다. 파일 검증 통과는 외형 품질·권리 확인을 뜻하지 않습니다.
6. **이 캐릭터 사용 → 메인 창에서 설정 저장**을 누릅니다. 준비만으로 바탕화면 캐릭터를 바꾸지 않습니다. 이동 시 측면을 보이고 멈춤·마우스 올림 시 정면으로 돌며 깨물 때 자체 입 좌표를 사용합니다. 기존 클릭 반응과 지킴이 안전 경계는 유지합니다.
7. 되돌리려면 같은 그림 창에서 **원본 2D 그림으로 돌아가기 → 이 캐릭터 사용 → 설정 저장**을 누릅니다. 원본 PNG와 이전 2D 리깅은 유지합니다. 손발 조각은 2D로 돌아간 뒤 편집하세요. 원본 입 위치를 바꿨다면 파생 동작도 다시 준비해야 합니다.

## 다른 전신 그림 예시

그림 창에서 **구름 정비사 → 예시 넣기**를 고르세요. 상아색 곱슬머리·노란 조끼·자주색 바지·청록색 부츠로 앞선 청록 머리 캐릭터와 구분합니다. 손은 비우고 몸통에서 떨어뜨리세요. 도구·긴 외투는 관절을 가릴 수 있습니다. 검사용 디자인이며 설명 준수나 리깅 성공을 보증하지 않습니다.

> 독창적인 작은 SD 구름 정거장 정비사 한 명. 정면을 향해 화면 중앙에 똑바로 서 있는 전신. 크고 둥근 머리, 짧고 풍성한 상아색 곱슬머리, 표정이 잘 보이는 짙은 눈, 연보라 눈썹, 작고 선명한 웃는 입. 크림색 긴팔 셔츠 위 짧은 샛노란 조끼, 차분한 자주색 바지, 두툼한 청록색 발목 부츠 두 짝. 두 팔은 몸통에서 조금 떨어뜨리고 팔꿈치·손목이 보이며 빈 손바닥은 조끼와 겹치지 않는다. 두 다리가 구분되고 부츠 사이에 틈이 있으며 무릎·발목이 보인다. 가슴 중앙에는 작은 민트색 육각형 천 패치 하나, 로고 없음. 단순하고 둥근 부피감과 읽기 쉬운 얼굴을 가진 친근하고 깔끔한 채색 일러스트. 머리·손·신발 밑창까지 전신이 화면 안에 들어오며 주변에 충분한 흰 여백. 단순한 흰색 배경. 캐릭터 한 명만, 손에 든 도구·모자·가방·떠다니는 소품·받침대·글자·다른 시점 없음.

새 그림을 생성하고 먼저 검토한 뒤 움직임을 준비하세요. 좌우 모습의 얼굴·의상 일관성, 양팔·다리 보행, 정면 대기·눈꺼풀, 클릭 반응, 양쪽 입 좌표를 확인합니다. 콘텐츠 검사를 통과해도 신체가 잘못 그려질 수 있습니다. 거절된 결과를 적용하지 마세요. 실제 이동 방향은 **설정 → 일반 → 걷기 방향 → 왼쪽/오른쪽 → 설정 저장**에서 정합니다. 미리보기 목록은 이 공통 설정을 바꾸지 않습니다. [방향 안내](GETTING_STARTED.md).

## 실제 실행 단계

| 단계 | 구현 |
| --- | --- |
| 승인한 그림 | 기존 SD 1.5/SDXL 생성·콘텐츠 검사 또는 이전에 승인한 로컬 PNG |
| 시점과 메쉬 | **TripoSR** 하나의 학습된 장면에서 8개 일관된 시점과 표면을 만든 뒤 자체 CUDA 프로세스 종료 |
| 관절과 스킨 | 별도 **CPU ViTPose** 프로세스가 사람형 17관절을 추정하고 앱이 표면에 투영해 12개 뼈대의 가중치를 계산한 뒤 종료 |
| 동작과 표정 | 별도 CPU 프로세스가 직접 구현한 보행·눈꺼풀·턱·미소 보정으로 12클립·256px 투명 437프레임을 저장한 뒤 종료 |
| 재생 | 원본·체크섬으로 검증한 PNG 묶음을 Qt에서 캐시 재생. 상주 추론 모델 없음 |

시점 일관성은 단일 이미지의 공유 3D 복원으로 확보합니다. 독립적으로 생성한 여러 그림을 합치는 방식, 학습된 영상 생성, UniRig 같은 전문 3D 뼈대·스킨 모델 호출은 아닙니다. 신체는 **포즈 추정 보조 리깅**이고 표정·동작은 직접 계산합니다. 더 큰 설계는 [구조 문서](STAGED-CHARACTER-PIPELINE.md)를 참고하세요.

앱 안에서는 모델 준비를 하나씩 실행합니다. 셸 없이 실행하며 Windows에서는 시작 전에 자체 프로세스 작업에 묶어 종료를 관리합니다. 취소 시 최종 종료까지 기다립니다. 종료를 확인하지 못하면 다른 준비 전에 Pawzura를 다시 시작해야 합니다. 사용자의 Ollama 서비스나 무관한 GPU 앱은 종료하지 않습니다.

## 하드웨어·다운로드·라이선스

- 현재 이 경로는 **VRAM 8GB 이상 NVIDIA CUDA GPU**와 준비된 격리 Python 3.12 그림 실행환경이 필요합니다. 2·4·6GB 안내는 그림 생성·2D 모션용이며 3D 경로를 활성화하지 않습니다.
- **TripoSR 가중치 약 1.7GB 추가**, 기존 CPU 포즈 가중치 약 350MB가 없다면 해당 다운로드, 작은 소스·라이브러리, 중간 결과·프레임 공간이 필요합니다. 기존 [그림 실행환경 조건](CREATIVE-ART.md)도 적용합니다. 전체 용량이 가용 메모리는 아니므로 다른 큰 작업은 직접 정리하세요.
- [TripoSR 코드](https://github.com/VAST-AI-Research/TripoSR)와 [가중치](https://huggingface.co/stabilityai/TripoSR)는 **MIT**입니다. [DINO ViT-B/16](https://huggingface.co/facebook/dino-vitb16) 설정은 **Apache-2.0**이며 별도 사전학습 가중치를 받지는 않습니다. 필요한 학습 구성은 TripoSR 체크포인트에 포함됩니다.
- [ViTPose base simple](https://huggingface.co/usyd-community/vitpose-base-simple)은 **Apache-2.0**입니다. 고정 revision·해시와 구성요소 조건은 [모션 카탈로그](../../art_runtime/motion_catalog.json), [소스 기록](../../art_runtime/triposr-sources.json), [고지](THIRD-PARTY-NOTICES.md)에 있습니다. 앱 MIT는 이 조건이나 원본 그림 모델의 OpenRAIL 조건을 대체하지 않습니다.

공식 소스 원본을 로컬에 유지합니다. 별도 수정 사본에서는 사용하지 않는 두 선택 import를 지연해 torchmcubes 컴파일 없이 자체 표면 추출을 씁니다. 생성된 실행 코드는 받지 않으며 저장소·EXE에 모델 가중치를 넣지 않습니다.

## 복구와 로컬 파일

원본 해시·백엔드 버전·관련 입 설정으로 단계 캐시를 구분합니다. 재사용 전에 실제 파일·크기·해시를 확인합니다. 원본·백엔드가 바뀌면 후속 결과가 무효화되고 입 위치를 바꾸면 리깅·프레임 저장을 다시 합니다. 실패·취소 시 이전 캐릭터를 유지하며 재시도 시 호환되는 완료 단계를 재사용합니다.

`%LOCALAPPDATA%/Pawzura` 아래 `artwork`는 원본 PNG, `motion`은 검증한 ZIP, `motion-jobs`는 중간 결과, `art-runtime`은 격리 환경·모델·소스 원본/수정본·고지입니다. 백업하려면 설정과 원본·모션 폴더를 함께 보관하세요. 묶음에 프롬프트·허용 목록·브라우저 데이터를 넣지 않습니다. 개인 폴더를 공개하지 마세요. 배포 검사는 이 폴더와 이름을 바꾼 모션 묶음·모델 체크포인트를 거절합니다. [개인정보](PRIVACY.md).

모션이 없거나 손상되면 원본 2D로 표시하고 그림 창에서 재준비 안내를 보여줍니다. 대체 표시는 3D 준비 성공이 아닙니다. 기존 화면 복구도 오래된 동작을 취소합니다.

## 확인한 결과와 한계

2026-11-03 Windows 10, RTX 2070 Max-Q **8GiB**, RAM 약 32GiB에서 소스를 확인했습니다. 메인 CPython 3.14.7/Qt 6.12, 작업 환경 CPython 3.12.14/PyTorch 2.7.1 CUDA 11.8입니다. 이전에 승인한 독창적 QA 그림 하나로 실제 복원 → 자동 포즈·가중치 → 437프레임을 **197.26초**에 만들었습니다. 모델 파일은 캐시되어 있었으며 TripoSR의 PyTorch 최대 할당은 **1936.12MiB**입니다. 드라이버·디스플레이·다른 앱 사용량은 제외하므로 최소 VRAM 보증이나 첫 다운로드 소요 시간이 아닙니다.

이후 native 소스 앱의 그림 창에서 검증된 단계를 재사용하고 저장·적용해 현재 모니터 작업 영역 바닥에서 **116px** 걸었습니다. 정면 멈춤·클립 입 좌표·가상 깨물기 콜백 1회·취소 동작 억제·영한 다크/라이트 일반/최소 크기 총 8개 위젯 렌더를 확인했습니다. 실제 대상 탐색·창 닫기는 차단했습니다. 새 그림 생성, 실제 차단 앱 닫기, OS 입력 E2E, 패키징 EXE, 다중 모니터, 새 경로의 Windows 11 검증은 아닙니다.


같은 8GiB PC의 추가 소스 검사: 기본 **구름 정비사** 예시로 새 SDXL 그림을 생성하고 기존 콘텐츠 검사를 통과하는 데 **184.52초**, 포즈 추정 보조로 437프레임을 준비하는 데 **160.44초** 걸렸습니다. 비전 모델의 입 추정이 너무 낮아 실제 입을 정규화 좌표 `(0.49, 0.375)`에 직접 표시했으며 신체 관절·가중치는 자동 추정했습니다. native 소스 앱에서 방향을 저장해 새 캐릭터가 작업 영역 바닥에서 **왼쪽 100px·오른쪽 101px** 이동했고, 반대편 가상 대상을 깨문 뒤 선택 방향 복귀와 화면 복구·설정 재열기 후 왼쪽 유지도 확인했습니다. 테스트 소유 위젯 조작이며 OS 입력 E2E는 아닙니다. 그림의 일부 색이 설명과 다르고 작은 흰 배경 조각이 남았으며 복원한 얼굴·가장자리가 흐려지고 일부 팔다리 이음새가 남았습니다. 파일·콘텐츠 검증 통과를 이런 외형 결함의 통과로 취급하지 않습니다.

품질은 고르지 않습니다. 점 기반 렌더 가장자리가 거칠고 손목·옷이 변형되거나 발이 미끄러질 수 있습니다. 추정한 측·후면은 원본과 다를 수 있고 인사·표정 보정은 작거나 엉뚱한 위치에 나타날 수 있습니다. 포즈 신뢰도는 올바른 3D 신체를 보증하지 않습니다. 실제로 연결된 실험 기능이며 **기본 도형보다 더 예쁜 애니메이션을 보증하지 않습니다.** 결과가 나쁘면 원본을 유지하세요.

이후 실제 경계 검사에서 125% 왼쪽 모니터 진입 시 native 도구 창이 반복 확대되는 문제를 발견했습니다. 논리 크기 고정·이동할 화면 명시·크기 변경 이벤트 보정으로 수정했습니다. 새 그림도 해당 실제 경계에서 크기·바닥·선택 방향 검사를 통과했고, 별도 모델 없는 검사 도구도 100%/125% 양방향 238샘플을 통과했습니다. 다른 배치와 Windows 11은 별도 검사가 필요합니다. [검사 반복 방법](GETTING_STARTED.md).

[캐릭터 로컬 저장과 재사용](CHARACTER-LIBRARY.md): 승인한 그림·동작 버전을 자동 보관하며 모델 없이 픽셀·클립을 불러옵니다. 중간 준비 결과는 단계별 지문으로 재사용합니다.

## 자세 보정과 이전 버전 보관

기존 사람형 리깅은 깊이 보정 전 관절로 몸통 기준점을 만들고 팔다리에는 보정 후 관절을 써서 좌표 기준이 달랐습니다. 구름 정비사 예시에서는 추정 몸통 각도가 약 −17°로 과장됐습니다. 이제 같은 보정된 관절을 사용하며, 몸통이 중립 상태에서 앞쪽 2°를 향하도록 최대 20° 범위에서 상체를 보정합니다. 머리·어깨 연결과 다리 길이·발 접촉 목표를 유지합니다. 직접 계산하는 자세 보정이며 새 학습형 모션 모델이나 해부학적으로 자연스러운 보행을 보증하는 기능은 아닙니다. 발 미끄러짐·흐린 가장자리·불완전한 스킨 이음새는 남을 수 있습니다.

저장된 사람형 두 캐릭터의 PNG와 검증한 장면을 재사용하고 CPU 리깅·프레임 저장만 실행했습니다. 이전 동작은 [로컬 보관함](CHARACTER-LIBRARY.md)에 유지합니다. 예전 저장본을 갱신하려면 그림 창에서 움직임을 다시 준비하고 새 버전을 검토·적용하세요. 움직임만 바꾸려고 그림을 재생성할 필요는 없습니다. 보관함에서는 이전·수정 클립 모두 추론 없이 불러올 수 있습니다.
