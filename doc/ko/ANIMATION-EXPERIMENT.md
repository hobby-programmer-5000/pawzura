# 단일 이미지 애니메이션 실험

**2026-11-03, Asia/Seoul.** Pawzura 소스 `f8bb0bf81b84a2478f4425ffaa42a9b98f63d58b` 기준 로컬 시제품 결과입니다. 앱 통합·릴리스가 아닙니다. 앞선 [조사](ANIMATION-RESEARCH.md)에 이어 메쉬·표정 추론을 실제 실행했습니다. One-to-All은 자원 사전 검사만 했으며 영상 추론은 하지 않았습니다.

## 환경과 입력

- Windows 10 x64 빌드 19045, NVIDIA RTX 2070 Max-Q VRAM 8 GiB, 시스템 RAM 약 32 GiB.
- 별도 Python 3.12.14 실험 환경, PyTorch 2.7.1+cu118, NumPy 1.26.4, SciPy 1.16.3, Pillow 12.0.0. 기존 CUDA 패키지를 읽기 전용으로 재사용했고 앱 의존성·설정은 변경하지 않았습니다.
- 이전 에이전트 QA에서 생성·승인한 독창적인 SDXL 그림 한 장을 사용했습니다. 사용자 그림·프롬프트가 아닙니다. 0.3.0 입력 PNG 해시를 검사했습니다. 몸동작 비교는 256×256이며 별도로 144픽셀 표시 미리보기를 제공합니다.
- 사용자 감시 기능·브라우저 프로필·저장 캐릭터·GPU 프로세스를 조작하지 않았습니다. 데스크톱 작업이 있는 환경의 관측값이며 독점 사용 기기의 성능 보장이 아닙니다.

## 눈으로 확인한 내용

깜빡임·행복한 표정 프레임에서 눈·입이 실제로 바뀌며 고개·시선 제어도 새 프레임을 생성했습니다. 이 입력에서는 표준 모델의 감은 눈·미소 선이 경량 모델보다 또렷해 보였지만 피부색 패치는 남았습니다. 두 결과를 비교할 수 있게 보관했습니다. 임시 얼굴 영역 합성으로 이 프레임을 걷는 메쉬와 함께 보여줍니다. 144픽셀에서도 표정을 구분할 수 있지만 얼굴이 부드러워지거나 피부색 패치가 보이는 문제는 추가 보완이 필요합니다. 현재 합성이 최종 혼합 방식은 아닙니다.

연결된 메쉬는 팔다리를 떨어진 조각처럼 취급하지 않습니다. 그러나 텍스처 한 장을 굽히므로 큰 자세에서 소매가 늘어나거나 윤곽이 변하며 가려진 신체를 그리지 못합니다. 팔·무릎 경로 추가도 렌더러 변경만큼 중요합니다. 기존 끝점 경로를 유지한 메쉬는 여전히 움직임이 작게 느껴질 수 있습니다.

초기 삼각형별 렌더에는 구멍·거친 경계가 있었습니다. 픽셀 중심 기반 초과표본 렌더·실루엣 여백·머리 고정 제약으로 줄였습니다. 정지 자세의 최대 좌표 오차는 0.0114픽셀, 임계값 적용 알파 영역의 교집합/합집합 비율은 0.9826이었습니다. 이 수치만으로 애니메이션 품질을 판정하지 않고 대표 자세·표정 모음 이미지도 확인했습니다.

첫 확대 모션은 좌우 대칭 팔을 함께 들어 올렸습니다. 수정한 실험 곡선에서는 수직 움직임이 번갈아 일어나며 상관계수 검사로 해당 실수를 방지합니다. 릴리스 앱에는 이 변경을 적용하지 않았습니다.

## 결과물과 검증 범위

로컬 무시 경로에 영문·한글 HTML 미리보기, 걷기·인사 비교 GIF, 별도임을 표시한 확대 모션 비교, 144픽셀 미리보기, 표정 확대, 투명 PNG 프레임, 소스·가중치 해시, 스크립트·자원 영수증을 보관합니다. QA 결과와 모델 파일은 Pawzura 배포에 포함하거나 이 문서와 함께 커밋하지 않습니다.

각 GIF를 다시 열어 24프레임인지 확인했습니다. 저장된 미리보기는 프레임당 40ms(25fps)이며 실시간 추론 검사나 앱의 전체 대기·이벤트 타이밍 재현이 아닙니다. 모델 출력의 유한값, 원본 해시, 정지 메쉬·알파 보존, 위상 동작을 검사했습니다. 같은 경로 비교와 확대 모션 비교는 구분합니다. 영문·한글 페이지를 격리된 헤드리스 Chrome 프로필로 렌더해 확인했습니다. 초기 영문 캡처의 글자 누락은 명시적 글꼴·화면 배율 고정·캡처 대기 시간 확대로 해결했습니다. 선택·멈춤 조작까지 자동 시험하지 않았으므로 전체 브라우저 UI E2E 통과로 표현하지 않습니다.

초기 RAM 모니터는 실제 추론 대신 작은 venv 실행기를 관측해 잘못된 7.89 MiB 값을 냈습니다. 위 결과에서 제외했습니다. 최종 값은 **실제 자식 프로세스 내부에서** OS 피크 카운터를 조회했습니다. 이전 실패·거친 결과도 로컬 증거로 유지합니다.

## 이 실험으로 내릴 수 있는 판단

**범위 추가:** 이후 요청한 측면 이동·입체적인 회전은 [이동 방향에 맞는 걷기와 입체감](DIRECTIONAL-ANIMATION.md)에서 따로 평가합니다. 아래 정면 시험만으로 그 요구를 충족하지 못하며 이후 3D 정지 시점도 아직 걷기의 근거는 아닙니다.

**메쉬와 표정 프레임을 미리 저장하는 방식은 제품 시제품으로 발전시킬 가치가 있습니다.** 이 GPU에서 실제 표정 생성이 가능하고 CPU 몸동작 준비 경로도 작동했습니다. One-to-All 기본 코드는 8 GiB용 실행 방법이 아니라는 점도 확인했습니다.

다음 작업은 얼굴 위치 자동 맞춤·혼합 개선, 덜 왜곡되는 전신 모션, 이벤트/클립 전환, 캐시 재생과 실패·취소 처리입니다. 별도로 텍스트 인코더 CPU 실행·양자화와 생성기/VAE 오프로딩을 적용한 One-to-All 실험은 가능성을 더 살펴볼 수 있으나 이번 결과가 그 성공을 입증하지는 않습니다. 앱 통합·새 EXE는 이번 실험 범위가 아닙니다.
